# 开发计划

## 第一步：规则引擎与状态机（已完成）

`HoldemGame.play_hand()` 现为本地演示兼容入口；联网调用 `start_new_hand()`、`legal_actions()` 和 `submit_action()`，每次行动后由调用方保存私密快照。

1. 明确持久状态：手牌 ID、阶段、庄位、当前行动者、筹码、投入、待行动集合、加注权限、底牌、牌堆、截止时间和状态版本。
2. 拆分开始手牌、查询合法操作、提交操作、自动推进阶段及结算入口。引擎不依赖 HTTP、WebSocket 或数据库。
3. 对非法操作返回明确错误，不擅自替玩家跟注或全下。
4. 修复只有一人能行动但仍需跟注的情况、非法过牌处理、短码全下的加注权及最小加注额、未跟注筹码返还和结算清理。
5. 实现按玩家身份生成可见状态，确保其他玩家未公开底牌和牌堆不出现在响应中。
6. 增加有断言的规则测试：行动顺序、多人全下、边池、平局、短码盲注、筹码守恒及重复结算防护。固定种子仅用于可复现测试。

已用规则测试验证：逐次完成两人和多人手牌；非法操作不改变状态；全下边池及平分；筹码守恒；结算只执行一次；私密信息按玩家隔离；快照可恢复。服务端仍需负责命令串行化、身份认证、截止时间执行和持久化事务。

## 当前里程碑：私人网页牌桌（v0.9.0-beta.3）

数据库迁移、FastAPI 接口、浏览器牌桌、WebSocket 同步和单机 HTTPS/WSS 部署已完成。管理员可建房、暂停／恢复和关闭房间，可为玩家签发恢复码、强制离座或移出；玩家可旁观、入座、买入、准备、连续游戏并查询私人记录。房间聊天已实现，但只保存在单个服务进程内存，删除房间或重启服务会清空。现有服务器需要使用单个 Uvicorn worker。玩法与边界见 [网页牌桌说明](web.md)，运维和备份见 [部署指南](deployment.md)。

## 下一阶段：GTO 模型与训练题（规划中）

1. **确定覆盖范围与资源门槛**：先选择可合法使用的 GTO 模型或求解方案，列出支持的玩家人数、有效筹码、下注尺度和翻前／翻后局面；准备参考局面验证结果。测量模型文件大小、峰值内存、CPU 占用、并发响应时间及对现有牌局延时的影响。只有服务器容量足够且不拖慢实时牌局时，才部署在当前服务器；否则改用独立机器或服务。
2. **实现独立分析服务**：定义局面输入与建议输出，校验位置、筹码、盲注、公共牌和行动序列的一致性；对不受支持的局面明确返回“无法分析”。分析进程设置资源上限、超时与缓存，不参与发牌、合法动作判定或结算，也不能访问其他玩家未公开的底牌。
3. **建立 GTO 训练题**：用经过验证的策略局面生成或整理题目，覆盖典型翻前和翻后选择。题目展示已知信息及动作选项，提交后展示动作频率、可用时的 EV、解析和错题回顾。训练环境与进行中的牌桌隔离；练习身份和进度如何保存，需要在实施前确定。
4. **验收**：对照参考结果测试策略输出；测试不支持的局面、超时、模型不可用和并发负载；确认训练题不会泄露实时对局私密信息，并在目标服务器上实测资源占用后再决定是否上线。
