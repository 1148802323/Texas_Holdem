# 开发计划

## 第一步：规则引擎与状态机（已完成）

`HoldemGame.play_hand()` 现为本地演示兼容入口；联网调用 `start_new_hand()`、`legal_actions()` 和 `submit_action()`，每次行动后由调用方保存私密快照。

1. 明确持久状态：手牌 ID、阶段、庄位、当前行动者、筹码、投入、待行动集合、加注权限、底牌、牌堆、截止时间和状态版本。
2. 拆分开始手牌、查询合法操作、提交操作、自动推进阶段及结算入口。引擎不依赖 HTTP、WebSocket 或数据库。
3. 对非法操作返回明确错误，不擅自替玩家跟注或全下。
4. 修复只有一人能行动但仍需跟注的情况、非法过牌处理、短码全下的加注权及最小加注额、未跟注筹码返还和结算清理。
5. 实现按玩家身份生成可见状态，确保其他玩家未公开底牌和牌堆不出现在响应中。
6. 增加有断言的规则测试：行动顺序、多人全下、边池、平局、短码盲注、筹码守恒及重复结算防护。固定种子仅用于可复现测试。

已用规则测试验证：逐次完成两人和多人手牌；非法操作不改变状态；全下边池及平分；筹码守恒；结算只执行一次；私密信息按玩家隔离；快照可恢复。服务端仍需负责命令串行化、身份认证、截止时间执行和持久化事务。

## 后续顺序

1. 数据模型与迁移（已完成本地版）：牌局、玩家会话、座位、买入、手牌、动作、结算、恢复状态。见 [数据库说明](database.md)。
2. 后端：管理员验证、邀请、Cookie 会话、房间接口、实时通信及超时执行。
3. 前端：管理员管理、邀请入座、牌桌操作、个人记录。
4. 完善超时、连续开局、重连、服务重启恢复及多人联调。
5. 部署：HTTPS/WSS、环境配置、日志和备份恢复。

前后端框架与数据库产品尚未初始化；目录结构不表示相关功能已实现。
