# 数据库与持久化

当前使用 Python 标准库 `sqlite3`，无需额外依赖；数据库文件应放在服务器受保护的数据目录，不能放入前端静态资源目录。`001_initial.sql` 建立结构，`002_observers.sql` 支持旁观与离桌记录，`003_live_play.sql` 增加准备、持续牌局和阶段计时，`004_player_recovery.sql` 增加身份恢复及管理记录；`PokerStore.initialize()` 启动时自动迁移到 v4。

## 房间规则

`max_buyin_stack` 是**买入后的在桌筹码上限**。买入额度可以自由选择，但必须大于 0 且 `当前在桌筹码 + 买入额 <= 上限`。历史累计买入不参与此上限计算；赢牌超过上限时保留所得筹码，之后只能等筹码低于上限再补买。买入仅限两手牌之间。

房间可使用自由昵称，或预设昵称列表。同一房间内有效昵称采用去除首尾空格及大小写折叠后的值比较；每个座位只能有一位有效玩家。玩家可先以昵称旁观，入座后才能买入；站起后筹码继续与该身份绑定。正在参与手牌的玩家不能换座、站起或离开。退出时剩余筹码转入累计离桌兑出，身份令牌失效；再次使用相同昵称会建立新身份，无法访问旧身份的私人历史。玩家首次加入时获得随机会话令牌，数据库只保存其 SHA-256 摘要。网页接口通过 `HttpOnly` Cookie 保存令牌，并在 HTTPS 下启用 `Secure`。

管理员“删除牌桌”将 `rooms.status` 设为 `closed`，隐藏管理列表并禁止新玩家加入，不物理删除买入或手牌行。正在进行的手牌保留至结算，此后不再自动开局；原玩家仍可凭现有令牌查看历史。

管理员可为有效玩家签发 15 分钟有效的一次性恢复码。数据库只保存 SHA-256 摘要；再次签发会撤销此前未使用的恢复码。玩家在新设备提交恢复码后沿用原身份、座位、筹码和历史，原令牌立即失效，当前手牌和截止时间不变。管理员可强制离座或移出玩家；若该玩家参与当前手牌，操作记录在 `pending_admin_action`，同手结算事务中执行。强制离座保留筹码和身份，移出则将结算后的筹码转入 `total_cashout` 并使令牌及恢复码失效。

## 主要表

| 表 | 用途 |
| --- | --- |
| `rooms`, `allowed_nicknames` | 盲注、人数、买入上限、各阶段时限、游戏运行状态及下一手时间、昵称规则 |
| `room_players` | 身份、可空座位、当前筹码、累计买入、离桌兑出、准备/开局确认、待结算管理操作和令牌摘要 |
| `buyins` | 每笔买入金额及前后筹码；请求 ID 防重复 |
| `hands`, `hand_players` | 手牌、庄位、参与者、盲注实付、起止筹码、派彩与返还 |
| `hand_actions` | 玩家动作、实际投入、底池、版本及请求 ID |
| `player_recovery_codes` | 一次性恢复码摘要、玩家、过期、使用和撤销时间 |
| `room_admin_events` | 签发/使用恢复码、排队/执行管理操作和删除牌桌的审计记录 |

`hands.private_snapshot` 包含底牌、剩余牌堆、当前决策时限、暂停剩余时间、全下投票、两次公共牌与分池结果，是服务端恢复牌局所需的**私密数据**。玩家界面只能调用 `player_view()` 或 `hand_history()`，不能访问 `load_game()` 或数据库原始行。管理员概览由 `room_overview()` 提供；HTTP 接口在访问前验证管理员会话。

公开的昵称盈亏按 `当前筹码 + 累计离桌兑出 − 累计买入` 计算；手牌进行期间使用上一次结算后的筹码，不将尚未结算的底池算入盈亏。同一昵称退出后重新加入，公开盈亏会按昵称汇总，但私人手牌历史仍按身份 ID 隔离。

## 一致性与恢复

- `buy_in()`、`start_hand()`、`apply_action()` 和 `set_deadline()` 在 SQLite `BEGIN IMMEDIATE` 事务中执行。同桌写入会串行化。
- 每次动作同时保存动作记录、最新私密快照和状态版本；结算时同一事务更新玩家筹码与 `hand_players` 结果。
- 买入、开手牌和动作使用调用方提供的请求 ID 防止重复执行；动作还必须带手牌 ID 与预期状态版本，以拒绝过期页面的请求。
- 重新创建 `PokerStore` 并调用 `load_game()` 可继续未完成手牌；截止时间随私密快照恢复。网页服务定期检查截止时间，超时可过牌则过牌，否则弃牌。
- 全下投票与暂停状态同样持久化；投票超时由未投者默认选择发一次。若一个边池的所有有资格玩家选择发两次，该边池在两块公共牌上分别结算；其他底池仍可只用第一块牌。
- `rooms.next_hand_at` 记录结算后的下一手计划时间；服务重启后调度器继续运行。准备和二次确认仅用于启动连续牌局，不在每手结算后重置。
- 身份恢复和管理操作也在 `BEGIN IMMEDIATE` 事务中执行。待执行的强制离座/移出随数据库重启恢复，并在本手结算时原子执行；若不足两名有资格玩家，自动牌局停止。
- 使用 `deploy/sqlite_data.py` 的 SQLite 在线备份与恢复工具定期制作快照，备份文件与在线库具有相同的私密性要求；具体演练步骤见 [部署与备份准备](deployment.md)。
