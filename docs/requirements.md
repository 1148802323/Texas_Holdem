# 首版需求

## 已确认

- 玩家无需注册或登录；只有管理员可以访问管理页面。
- 管理员创建牌局，设置大小盲、玩家通过买入可达到的在桌筹码上限、牌桌人数和入座昵称规则。
- 创建后生成邀请链接，玩家从网页自由加入。
- 同一场牌局中，一个昵称最多占用一个座位。
- 记录每个昵称的买入，玩家可以查看属于自己的牌局记录。
- 所有牌局记录保存到管理员的数据库。
- 刷新后恢复身份、座位和最新对局状态。
- 未公开的底牌不得泄露。
- 基础对局包含合法操作校验、全下与边池、超时、连续开局和断线重连。

## 身份与隐私约束

- 昵称是显示名称，不能作为身份证明。首次加入需签发私密会话凭证，刷新时通过安全 Cookie 恢复。
- 已占用昵称不可仅凭重新输入接管；不同场次的相同昵称不能自动共享记录权限。
- 管理员入口必须有身份验证；隐藏网址不足以保护管理权限。
- 当前底牌、未公开历史底牌、牌堆等私密数据仅保存在受保护的服务端，按访问者权限输出。
- 换设备或清除凭证后的身份恢复方案，首版可由管理员重置凭证。

## 已确认的买入规则

- 房间设置 `max_buyin_stack`，限制玩家每次买入**之后**的在桌筹码；并非累计买入上限，也不限制对局赢得的筹码。
- 例如上限 2000：当前筹码 0 时最多买入 2000；当前筹码 400 时最多补入 1600；已赢到 2200 时保留 2200，暂不能继续买入。
- 每次买入都要大于 0，并逐笔记录；牌局进行中不可买入，同一请求重复发送不可重复加筹码。

## 待实现时明确的配置细节

- 补充买入是否需要管理员批准；当前持久化服务默认允许玩家在两手牌之间自行补买。
- 昵称自由输入还是管理员预设名单；明确昵称比较及保留规则。
- 行动时限、暂离规则、离场后重新入座规则。

## 术语与账本

- 牌局：一次房间内的完整游戏会话，可包含多手牌。
- 手牌：从发牌到结算的一轮。
- 买入：向该牌局的玩家筹码账户增加虚拟筹码，逐笔记录。
- 净盈亏：在结算完成时，已带出筹码＋剩余筹码－累计买入。
- 买入、返还、派彩等变化必须可核对并防重复执行；中途加入及补充筹码在手牌间生效。
